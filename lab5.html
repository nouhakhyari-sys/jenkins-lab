Lab 5 – Deploy with Docker

Scenario. You are the DevOps engineer of a small start-up. Its product is the calculator, now a small web application. The team wants every change to be built, tested, packaged in a Docker image, versioned and deployed automatically, with a person approving the production release.

In this lab you build that pipeline: the first part of the chapter (build, test, release, delivery) and the Docker part, together. Each part adds one idea of the course to the pipeline.

PartWhat you addCourse idea
1Docker inside JenkinsBind mount, volume, client / daemon
2Read the app and its DockerfileDockerfile, image as code
3Parallel testsBuild and test, unit vs integration
4A versioned imageRelease: the image is the artifact, tags
5Staging and a smoke testPort mapping, staging, container lifecycle
6Production with approvalDelivery vs deployment, build once deploy many
7ChallengesRegistry, security scan, rollback

Before you start

  • Docker Desktop (or Docker on Linux) is installed and running.
  • Labs 3 and 4 are done: you know parameters, junit, archiveArtifacts and input.
  • The project you will deploy (Java code, tests, Dockerfile): 📂 github.com/nouhakhyari-sys/jenkins-labs-template/tree/main/lab5/calc-web. Jenkins downloads it by itself: nothing to copy.
  • Your jenkins-labs repository is ready for the hand-in (folder lab5). Create report.txt now (template on page 8) and fill it in as you go.
Jenkins in Docker or on Windows? Every script exists in two versions, as in the previous labs: sh for Jenkins in Docker, bat for Jenkins installed on Windows. Part 1 is also different for each.
