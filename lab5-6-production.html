Lab 5 · Deploy with Docker

6. Production, with Approval

🎯 Why this step? The last step of the chapter: delivery vs deployment. A person approves the production release (continuous delivery), and production runs the same image that passed staging: build once, deploy many (the Docker part of the course).

Step 1: a parameter

Replace your whole parameters { } block with this one. The new choice line goes inside the block, under SIMULATE_BUG, before the closing }:

The whole parameters block (Docker and Windows)
    parameters {
        booleanParam(name: 'SIMULATE_BUG', defaultValue: false,
                     description: 'Tick to put a bug in the calculator')
        choice(name: 'DEPLOY_ENV', choices: ['staging', 'production'],
               description: 'staging: stop after staging. production: staging, approval, then production.')
    }
⚠️ Common error: the choice line pasted after the } of parameters. Jenkins then refuses the script. Both parameters must be between parameters { and its }.

Step 2: the production stage

Production is the same deployment as staging, with a few differences. Compare:

Staging (part 5)Production
Container namecalc-stagingcalc-prod
Port of your computer80818082 (staging keeps running on 8081)
Image${IMAGE}:${VERSION}the same one: no new docker build
Before deployingnothinga person clicks Deploy (the input step of Lab 3)
Runs whenthe build is greenthe build is green and DEPLOY_ENV = production

🔮 Predict first. Write your answer down before you run, then compare.
  1. With DEPLOY_ENV = staging, which stage will be skipped?
  2. With production, the run stops and waits. How many images will exist for this run, and how many containers?

Run and check

  1. Build with Parameters, DEPLOY_ENV = production. The run deploys staging, then waits: click Deploy.
  2. Open http://localhost:8081 and http://localhost:8082: the same version in staging and production.
  3. docker ps: two containers, one image.
Show the explanation
  • With staging, the first expression of allOf is false: production is skipped.
  • With production: one image, two containers (slide Docker Images vs Container Instances). The input is what makes it continuous delivery; remove it and every green build reaches production: continuous deployment.
  • Production does not rebuild: a new build could include a different base image or library. Deploying the tested tag is the proof that production runs what staging tested.
Show the full Jenkinsfile (Jenkins in Docker)
pipeline {
    agent any

    options {
        timestamps()
    }

    parameters {
        booleanParam(name: 'SIMULATE_BUG', defaultValue: false,
                     description: 'Tick to put a bug in the calculator')
        choice(name: 'DEPLOY_ENV', choices: ['staging', 'production'],
               description: 'staging: stop after staging. production: staging, approval, then production.')
    }

    environment {
        IMAGE   = 'calc-web'
        VERSION = "1.0.${BUILD_NUMBER}"
    }

    stages {
        stage('Checkout') {
            steps {
                dir('app') {
                    git url: 'https://github.com/nouhakhyari-sys/jenkins-labs-template.git', branch: 'main'
                }
            }
        }
        stage('Build') {
            steps {
                dir('app/lab5/calc-web') {
                    sh 'javac --release 21 -d build/classes src/*.java test/*.java'
                }
            }
        }
        stage('Tests') {
            parallel {
                stage('Unit tests') {
                    steps {
                        dir('app/lab5/calc-web') {
                            sh "java -DsimulateBug=${params.SIMULATE_BUG} -cp build/classes CalculatorTest"
                        }
                    }
                }
                stage('Integration tests') {
                    steps {
                        dir('app/lab5/calc-web') {
                            sh "java -DsimulateBug=${params.SIMULATE_BUG} -cp build/classes ServerTest"
                        }
                    }
                }
            }
            post {
                always {
                    junit 'app/lab5/calc-web/build/test-results/*.xml'
                    archiveArtifacts artifacts: 'app/lab5/calc-web/build/test-results/*.xml'
                }
            }
        }
        stage('Package') {
            steps {
                dir('app/lab5/calc-web') {
                    sh 'jar cfe build/calculator-web.jar CalculatorServer -C build/classes .'
                }
                archiveArtifacts artifacts: 'app/lab5/calc-web/build/calculator-web.jar', fingerprint: true
            }
        }
        stage('Docker image') {
            when {
                expression { currentBuild.currentResult == 'SUCCESS' }
            }
            steps {
                dir('app/lab5/calc-web') {
                    sh "docker build --build-arg APP_VERSION=${VERSION} -t ${IMAGE}:${VERSION} ."
                }
                sh "echo ${IMAGE}:${VERSION} > image.txt"
                archiveArtifacts artifacts: 'image.txt'
            }
        }
        stage('Deploy to staging') {
            when {
                expression { currentBuild.currentResult == 'SUCCESS' }
            }
            steps {
                sh 'docker rm -f calc-staging || true'
                sh "docker run -d --name calc-staging -p 8081:8080 ${IMAGE}:${VERSION}"
                sh 'sleep 3'
                sh 'curl -s http://host.docker.internal:8081/add/2/3 | grep -x 5'
                echo "Application deployed successfully: http://localhost:8081 (version ${VERSION})"
            }
        }
        stage('Deploy to production') {
            when {
                allOf {
                    expression { params.DEPLOY_ENV == 'production' }
                    expression { currentBuild.currentResult == 'SUCCESS' }
                }
            }
            steps {
                input message: "Deploy ${IMAGE}:${VERSION} to production?", ok: 'Deploy'
                sh 'docker rm -f calc-prod || true'
                sh "docker run -d --name calc-prod -p 8082:8080 ${IMAGE}:${VERSION}"
                echo "Application deployed successfully: http://localhost:8082 (version ${VERSION})"
            }
        }
    }

    post {
        always {
            cleanWs()
        }
    }
}
Show the full Jenkinsfile (Jenkins on Windows)
pipeline {
    agent any

    options {
        timestamps()
    }

    parameters {
        booleanParam(name: 'SIMULATE_BUG', defaultValue: false,
                     description: 'Tick to put a bug in the calculator')
        choice(name: 'DEPLOY_ENV', choices: ['staging', 'production'],
               description: 'staging: stop after staging. production: staging, approval, then production.')
    }

    environment {
        IMAGE   = 'calc-web'
        VERSION = "1.0.${BUILD_NUMBER}"
    }

    stages {
        stage('Checkout') {
            steps {
                dir('app') {
                    git url: 'https://github.com/nouhakhyari-sys/jenkins-labs-template.git', branch: 'main'
                }
            }
        }
        stage('Build') {
            steps {
                dir('app/lab5/calc-web') {
                    bat 'javac --release 21 -d build/classes src/*.java test/*.java'
                }
            }
        }
        stage('Tests') {
            parallel {
                stage('Unit tests') {
                    steps {
                        dir('app/lab5/calc-web') {
                            bat "java -DsimulateBug=${params.SIMULATE_BUG} -cp build/classes CalculatorTest"
                        }
                    }
                }
                stage('Integration tests') {
                    steps {
                        dir('app/lab5/calc-web') {
                            bat "java -DsimulateBug=${params.SIMULATE_BUG} -cp build/classes ServerTest"
                        }
                    }
                }
            }
            post {
                always {
                    junit 'app/lab5/calc-web/build/test-results/*.xml'
                    archiveArtifacts artifacts: 'app/lab5/calc-web/build/test-results/*.xml'
                }
            }
        }
        stage('Package') {
            steps {
                dir('app/lab5/calc-web') {
                    bat 'jar cfe build/calculator-web.jar CalculatorServer -C build/classes .'
                }
                archiveArtifacts artifacts: 'app/lab5/calc-web/build/calculator-web.jar', fingerprint: true
            }
        }
        stage('Docker image') {
            when {
                expression { currentBuild.currentResult == 'SUCCESS' }
            }
            steps {
                dir('app/lab5/calc-web') {
                    bat "docker build --build-arg APP_VERSION=${VERSION} -t ${IMAGE}:${VERSION} ."
                }
                bat "echo ${IMAGE}:${VERSION}> image.txt"
                archiveArtifacts artifacts: 'image.txt'
            }
        }
        stage('Deploy to staging') {
            when {
                expression { currentBuild.currentResult == 'SUCCESS' }
            }
            steps {
                bat 'docker rm -f calc-staging 2>nul & exit /b 0'
                bat "docker run -d --name calc-staging -p 8081:8080 ${IMAGE}:${VERSION}"
                bat 'ping -n 4 127.0.0.1 >nul'
                script {
                    def answer = bat(script: '@curl -s http://localhost:8081/add/2/3', returnStdout: true).trim()
                    echo "Smoke test: /add/2/3 answered ${answer}"
                    if (answer != '5') {
                        error "Smoke test failed: expected 5 but got ${answer}"
                    }
                }
                echo "Application deployed successfully: http://localhost:8081 (version ${VERSION})"
            }
        }
        stage('Deploy to production') {
            when {
                allOf {
                    expression { params.DEPLOY_ENV == 'production' }
                    expression { currentBuild.currentResult == 'SUCCESS' }
                }
            }
            steps {
                input message: "Deploy ${IMAGE}:${VERSION} to production?", ok: 'Deploy'
                bat 'docker rm -f calc-prod 2>nul & exit /b 0'
                bat "docker run -d --name calc-prod -p 8082:8080 ${IMAGE}:${VERSION}"
                echo "Application deployed successfully: http://localhost:8082 (version ${VERSION})"
            }
        }
    }

    post {
        always {
            cleanWs()
        }
    }
}
Bonus: email notification (if you did Lab 3, part 8)

Add the success and failure blocks of the email part of Lab 3 to the post { } section, and put ${VERSION} in the subject: subject: "calc-web ${VERSION} deployed". Mailpit then shows which version reached which environment.

✅ Checkpoint 6: answer in report.txt, in your own words (one or two lines each).
  1. Is your pipeline continuous delivery or continuous deployment? Which line decides it?
  2. Staging and production run the same image. Why not rebuild the image for production?
See the answer
  1. Continuous delivery: every good version is ready for production, but a person approves it. The input step decides it (Deploy / Abort). Without input, every green build would go to production by itself: continuous deployment.
  2. Rebuilding could give a different image: a new base image, another library version, a new commit. Then production would run something that staging never tested. Deploying the same tag (calc-web:1.0.N) proves that production runs exactly what was tested: build once, deploy many.
