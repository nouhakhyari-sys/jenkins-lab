Lab 6 · Distributed Builds with Agents

3. A Windows Agent on your PC

🎯 Why this step? Some builds need Windows: a .NET program, a Windows installer, tests of a desktop app. A Windows agent is just agent.jar running on a Windows machine. Here, that machine is your own PC, so you see both sides of the connection.

Do you have Java on your PC?

In a Command Prompt: java -version. Version 17 or newer: continue. Not found or older:

  • install Eclipse Temurin 21 (JDK) from adoptium.net (tick Add to PATH during the installation), then open a new Command Prompt; or
  • skip this part and create a second Linux agent instead: Challenge 2 of part 8. In parts 4 and 5, replace windows by linux and bat by sh.

A. Create the node

  1. Manage Jenkins › Nodes › New Node. Name: windows-agent. Type: Permanent Agent (or Copy Existing Node from linux-agent, then change the fields). Create.
  2. Number of executors: 1. Remote root directory: C:\jenkins-agent. Labels: windows java. Usage: Only build jobs with label expressions matching this node. Launch method: Launch agent by connecting it to the controller (Use WebSocket: optional, as for linux-agent). Save.
  3. Click windows-agent. Under Windows, Jenkins shows two commands: curl.exe (download agent.jar) and java -jar agent.jar … with the secret. You can copy them from there.

B. Start the agent

Open a new Command Prompt (cmd, not PowerShell) and run these lines one by one, with your secret:

Start the Windows agent (Command Prompt)
mkdir C:\jenkins-agent
cd C:\jenkins-agent
curl.exe -sO http://localhost:8080/jnlpJars/agent.jar
java -jar agent.jar -url http://localhost:8080/ -secret PASTE_THE_SECRET_HERE -name windows-agent -webSocket -workDir "C:\jenkins-agent"
  1. Wait for INFO: Connected. Keep this window open: closing it stops the agent.
  2. Refresh Manage Jenkins › Nodes: three nodes, the controller and two agents online. Take the screenshot nodes.png (hand-in).
Jenkins on Windows: the controller and windows-agent are now on the same PC, in two different folders. In a company they would be two machines; the commands are the same, only the address in -url changes.
"'java' is not recognized as an internal or external command"

Java is not installed, or not in the PATH. Install Temurin 21 with Add to PATH, close the Command Prompt and open a new one. Jenkins on Windows works but java is unknown? Use the full path, for example "C:\Program Files\Eclipse Adoptium\jdk-21…\bin\java.exe" -jar agent.jar …

agent.jar prints a long list of options, then "'-name' is not recognized as an internal or external command"

The java command was cut into two lines when you copied it (the node page shows it wrapped). The first half ran without -name, so agent.jar printed its help; the second half ran alone. Paste the command into Notepad, make it one single line, then paste it into the Command Prompt. Use the secret of windows-agent, not the one of linux-agent: each node has its own.

"UnsupportedClassVersionError" when starting agent.jar

Your Java is too old for this version of Jenkins (it needs 17 or 21). Install Temurin 21 and open a new Command Prompt.

"is already connected to this controller"

The same agent is running twice (another window still open). Close the other window, or stop it with Ctrl + C, and start it once.

See the answer
  1. The build fails: the steps were running on that machine, and the connection is lost. Jenkins marks the agent offline. A company installs the agent as a Windows service (it starts with Windows, without a window), or uses a scheduled task.
