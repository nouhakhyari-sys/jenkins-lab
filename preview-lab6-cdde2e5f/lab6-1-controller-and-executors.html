Lab 6 · Distributed Builds with Agents

1. The Controller and its Executors

🎯 Why this step? Until now your Jenkins was the controller (the web page, the jobs) and also the only machine that built. Before adding agents, look at the place where builds really run: the node and its executors.

Look at your nodes

  1. Open Manage Jenkins › Nodes (address http://localhost:8080/computer/).
  2. There is one line: Built-In Node. That is the controller itself, when it builds. Read the columns: Architecture (the operating system), Free Disk Space, Response Time.
  3. Go back to the Jenkins home page. On the left: Build Queue (empty) and Build Executor Status, which lists the executors of the built-in node (usually 2), each Idle.

Fill the queue

  1. Manage Jenkins › Nodes › Built-In Node › Configure (gear icon or Configure on the left). Set Number of executors to 1. Save.
  2. Create a Pipeline job named slow-job with this script (sleep works on every OS: no sh or bat).
slow-job
pipeline {
    agent any
    stages {
        stage('Slow') {
            steps {
                echo "Running on ${env.NODE_NAME}"
                sleep time: 60, unit: 'SECONDS'
            }
        }
    }
}
🔮 Predict first. Write your answer down before you run, then compare.
  1. You click Build Now three times quickly. How many builds run at the same time? Where are the others?
  1. Click Build Now three times, quickly, and go to the Jenkins home page.
  2. Look at Build Executor Status (one build running) and Build Queue (the others). Hover over a waiting build: Jenkins says why it waits.
  3. When you have seen it, set the built-in node back to 2 executors.
Show the explanation

With 1 executor, Jenkins runs one build at a time. Builds #2 and #3 wait in the Build Queue, with the reason Waiting for next available executor. Each one starts when the previous one ends: the third finishes about 3 minutes after you clicked.

An executor is a slot for one build. More executors = more builds at the same time, but they share the same CPU: the rule of thumb is one executor per CPU core. To build more, you add machines: agents.

✅ Checkpoint 1: answer in report.txt, in your own words (one or two lines each).
  1. Your built-in node has 2 executors. Five teammates push at the same moment and each build takes 10 minutes. When does the last build finish? Explain with what you saw in the Build Queue.
  2. The Nodes page shows the operating system of the built-in node. What does yours say, and why? (Jenkins in Docker on a Windows PC: why is it not Windows?)
See the answer
  1. After 30 minutes. 2 builds run from 0 to 10 min, 2 more from 10 to 20, the last one from 20 to 30. The others wait in the Build Queue with “Waiting for next available executor”, exactly what you saw with 1 executor and 3 builds.
  2. Jenkins on Windows: Windows (amd64). Jenkins in Docker: Linux (amd64), because Jenkins runs inside a Linux container, even on a Windows PC: Docker Desktop runs a small Linux virtual machine. That is why Jenkins in Docker uses sh and Jenkins on Windows uses bat.
