9. Checklist and Help

Checklist

Required (parts 1 to 5):

  • ☐ You saw builds waiting in the Build Queue with 1 executor (part 1).
  • ☐ linux-agent is online, Architecture Linux (part 2).
  • ☐ windows-agent is online (or a second Linux agent, if you have no Java on your PC) (part 3).
  • ☐ where-am-i: each stage on the right node (part 4).
  • ☐ build-once: built on Linux, run on both agents in parallel, hello.jar archived (part 5).
  • ☐ report.txt: checkpoints 1 to 5 answered, and your quiz score.

Bonus:

  • ☐ Part 6: 0 executors on the controller, the waiting stage fixed, the offline test done; checkpoint 6 answered.
  • ☐ One or more challenges of part 8.

For your final project (finish at home if needed):

  • ☐ Part 7: docker-agent online, image-on-agent green; checkpoint 7 answered.

Hand in your work

In the lab6 folder of your jenkins-labs repository (guide: How to hand in your work):

  • report.txt: the template below, filled in. It counts most: short answers in your own words;
  • Jenkinsfile: your build-once script;
  • nodes.png: the Nodes page with the controller and your two agents online (hide the secrets);
  • parallel.png: Blue Ocean or Pipeline Overview with the Linux and Windows branches;
  • docker-agent.png (part 7): the console with Running on docker-agent and the Hello line, and your docker-agent/Dockerfile;
  • bonus: challenge.png, a screenshot proving each challenge you did.

Clean up (optional)

Stop the Windows agent (Ctrl + C in its window) and the Linux agent (docker stop linux-agent). The nodes stay in Jenkins, offline: docker start linux-agent and the java -jar agent.jar … line bring them back. Keep docker-agent for your final project: docker start docker-agent after a restart of your PC.

Troubleshooting

The build waits forever, the console is empty

Hover over the build in the Build Queue (home page) and read the reason:

  • There are no nodes with the label ‘…’: a typo in the label (labels are case-sensitive), or the node does not have that label. Compare with Manage Jenkins › Nodes › (agent) › Configure › Labels.
  • ‘linux-agent’ is offline: start the agent again (docker start linux-agent, or the java -jar line).
  • Waiting for next available executor with agent any: the controller has 0 executors and the agents only accept labelled jobs (part 6).
linux-agent: docker logs shows "Failed to connect" / "Connection refused" / "UnknownHostException host.docker.internal"

The container cannot reach Jenkins. Check that Jenkins opens on http://localhost:8080 in your browser; with another port, change JENKINS_URL. Keep --add-host=host.docker.internal:host-gateway in the command (needed on Linux). Then docker rm -f linux-agent and run the line again.

linux-agent: "403 Forbidden", "is not a valid agent name" or the container stops at once

Wrong secret or wrong name. docker logs linux-agent shows the error. Copy the secret again from the node page and check that JENKINS_AGENT_NAME is exactly the node name. Remove and start the container again.

windows-agent: "'java' is not recognized" or "UnsupportedClassVersionError"

No Java, or Java older than 17. Install Eclipse Temurin 21 (JDK) with Add to PATH, and use a new Command Prompt.

Error: Cannot run program "nohup" (on windows-agent)

An sh step was sent to Windows. Windows agents need bat (or powershell). Check the label of the stage and the step.

Error: Cannot run program "cmd" (on linux-agent)

The opposite: a bat step was sent to the Linux agent. Use sh, or check the label.

Error: No such saved stash ‘…’

The name in unstash is not the name in stash (case-sensitive), or the stage that stashes did not run before. The Build stage must come first and use the same name.

Error: Unable to access jarfile hello.jar

unstash 'app' is missing in that stage: the jar is on another agent. Add it before java -jar.

Jenkins shows "Jenkins URL is empty" or the node page commands use a wrong address

Manage Jenkins › System › Jenkins URL: set http://localhost:8080/ (your port) and Save. The commands on the node pages use this address.

Jenkins on Windows: a firewall window appears when the agent starts

Windows asks whether Java may use the network. Click Allow (private networks). The agent only talks to Jenkins on your own PC.
