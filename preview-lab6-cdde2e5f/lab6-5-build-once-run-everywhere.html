Lab 6 · Distributed Builds with Agents

5. Build Once, Run Everywhere

🎯 Why this step? A release is built once, then the same file is tested where customers use it. Here: compile a Java program on Linux, then run that exact jar on Linux and on Windows, at the same time. The catch: each agent has its own workspace, so the jar has to be carried from one to the other.

The program

A small Java program that says where it runs. The pipeline writes it itself with writeFile: no Git repository needed.

Hello.java (written by the pipeline)
public class Hello {
    public static void main(String[] args) {
        System.out.println("Hello from " + System.getProperty("os.name")
            + ", Java " + System.getProperty("java.version"));
    }
}

Complete the pipeline

Create a Pipeline job named build-once. Copy this script and replace each ____. You need: none, linux, windows, stash, unstash, parallel, bat.

build-once, to complete
pipeline {
    agent ____
    stages {
        stage('Build on Linux') {
            agent { label '____' }
            steps {
                writeFile file: 'src/Hello.java', text: '''
public class Hello {
    public static void main(String[] args) {
        System.out.println("Hello from " + System.getProperty("os.name")
            + ", Java " + System.getProperty("java.version"));
    }
}
'''
                sh 'javac --release 17 -d classes src/Hello.java'
                sh 'jar cfe hello.jar Hello -C classes .'
                ____ name: 'app', includes: 'hello.jar'
                archiveArtifacts artifacts: 'hello.jar', fingerprint: true
            }
        }
        stage('Run everywhere') {
            ____ {
                stage('Linux') {
                    agent { label 'linux' }
                    steps {
                        ____ 'app'
                        sh 'java -jar hello.jar'
                    }
                }
                stage('Windows') {
                    agent { label '____' }
                    steps {
                        unstash 'app'
                        ____ 'java -jar hello.jar'
                    }
                }
            }
        }
    }
}
Show the solution
pipeline {
    agent none
    stages {
        stage('Build on Linux') {
            agent { label 'linux' }
            steps {
                writeFile file: 'src/Hello.java', text: '''
public class Hello {
    public static void main(String[] args) {
        System.out.println("Hello from " + System.getProperty("os.name")
            + ", Java " + System.getProperty("java.version"));
    }
}
'''
                sh 'javac --release 17 -d classes src/Hello.java'
                sh 'jar cfe hello.jar Hello -C classes .'
                stash name: 'app', includes: 'hello.jar'
                archiveArtifacts artifacts: 'hello.jar', fingerprint: true
            }
        }
        stage('Run everywhere') {
            parallel {
                stage('Linux') {
                    agent { label 'linux' }
                    steps {
                        unstash 'app'
                        sh 'java -jar hello.jar'
                    }
                }
                stage('Windows') {
                    agent { label 'windows' }
                    steps {
                        unstash 'app'
                        bat 'java -jar hello.jar'
                    }
                }
            }
        }
    }
}
🔮 Predict first. Write your answer down before you run, then compare.
  1. The Linux and Windows stages start together. Which one finishes first? What will each one print?
  2. You remove unstash 'app' from the Windows stage. Which error do you expect?

Run and observe

  1. Build Now. Open the run in Blue Ocean (/blue) or Pipeline Overview: Run everywhere splits into two branches. Click each one: Hello from Linux… and Hello from Windows 11… (or Windows 10). Take the screenshot parallel.png.
  2. On the build page, Build Artifacts shows hello.jar (from archiveArtifacts). The stash is not listed anywhere.
  3. Remove unstash 'app' from the Windows stage, run, read the error, and put it back.
Show the explanation
  • The two stages run on two machines at the same time; their logs are separated in Blue Ocean. The Windows one prints your Windows version and the Java of your PC; the Linux one prints Linux and Java 21 from the image.
  • Without unstash: Error: Unable to access jarfile hello.jar. The Windows workspace is a folder on your PC; hello.jar was created in the workspace of linux-agent, inside the container.
  • javac --release 17 makes bytecode for Java 17 and newer, so it runs on the agent's Java 21 and on a PC with Java 17.
✅ Checkpoint 5: answer in report.txt, in your own words (one or two lines each).
  1. Why does the Windows stage need unstash, although the Build stage ran a few seconds earlier in the same pipeline?
  2. stash or archiveArtifacts: which one hands the jar to the next stage, and which one lets you download it next month? Why not use one for both?
  3. The jar was compiled on Linux and ran on Windows. What makes that possible, and why is "build once" important for a release?
See the answer
  1. Each node has its own workspace, on its own machine. Build ran on linux-agent, so hello.jar is in linux-agent's folder, not on your PC. unstash copies it from the controller into the Windows workspace. (The Linux stage needs it too: it may get another workspace folder.)
  2. stash passes files to a later stage of the same run, and is deleted at the end of the run. archiveArtifacts keeps files with the build, to download from the build page. A stash is not visible in the web page; an archive is not given to the next stage.
  3. Java bytecode (the .class files in the jar) runs on any Java Virtual Machine, on any OS (--release 17 makes it run on Java 17 or newer). Build once: what you test on Windows is exactly the file you deliver, not a second build that could differ.
