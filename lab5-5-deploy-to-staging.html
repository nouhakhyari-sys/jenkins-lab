Lab 5 · Deploy with Docker

5. Deploy to Staging

🎯 Why this step? Tests passed, the image exists. Now it must run somewhere like production, before real users see it: staging. A smoke test then checks automatically that the deployed app answers. This is where port mapping (slides Port Mapping) becomes real.

Staging is a container named calc-staging, on port 8081 of your computer. The app listens on port 8080 inside the container (the EXPOSE of the Dockerfile). Add this stage after Docker image. ✍️ Your turn: fill in the blanks.

Deploy to staging, to complete (Jenkins in Docker)
        stage('Deploy to staging') {
            when {
                expression { currentBuild.currentResult == 'SUCCESS' }
            }
            steps {
                sh 'docker rm -f calc-staging || true'
                sh "docker run -d --name calc-staging -p ____:____ ${IMAGE}:${VERSION}"
                sh 'sleep 3'
                sh 'curl -s http://host.docker.internal:____/add/2/3 | grep -x ____'
                echo "Application deployed successfully: http://localhost:8081 (version ${VERSION})"
            }
        }
Deploy to staging, to complete (Jenkins on Windows)
        stage('Deploy to staging') {
            when {
                expression { currentBuild.currentResult == 'SUCCESS' }
            }
            steps {
                bat 'docker rm -f calc-staging 2>nul & exit /b 0'
                bat "docker run -d --name calc-staging -p ____:____ ${IMAGE}:${VERSION}"
                bat 'ping -n 4 127.0.0.1 >nul'
                script {
                    def answer = bat(script: '@curl -s http://localhost:____/add/2/3', returnStdout: true).trim()
                    echo "Smoke test: /add/2/3 answered ${answer}"
                    if (answer != '____') {
                        error "Smoke test failed: got ${answer}"
                    }
                }
                echo "Application deployed successfully: http://localhost:8081 (version ${VERSION})"
            }
        }
✍️ The blanks.
  1. -p ____:____ is -p HOST:CONTAINER. Which port is on your computer, which one in the container?
  2. The smoke test calls staging from Jenkins, through the port of your computer.
  3. It requires one exact answer: what does /add/2/3 return?
Show the solution (Jenkins in Docker)
        stage('Deploy to staging') {
            when {
                expression { currentBuild.currentResult == 'SUCCESS' }
            }
            steps {
                sh 'docker rm -f calc-staging || true'
                sh "docker run -d --name calc-staging -p 8081:8080 ${IMAGE}:${VERSION}"
                sh 'sleep 3'
                sh 'curl -s http://host.docker.internal:8081/add/2/3 | grep -x 5'
                echo "Application deployed successfully: http://localhost:8081 (version ${VERSION})"
            }
        }
Show the solution (Jenkins on Windows)
        stage('Deploy to staging') {
            when {
                expression { currentBuild.currentResult == 'SUCCESS' }
            }
            steps {
                bat 'docker rm -f calc-staging 2>nul & exit /b 0'
                bat "docker run -d --name calc-staging -p 8081:8080 ${IMAGE}:${VERSION}"
                bat 'ping -n 4 127.0.0.1 >nul'
                script {
                    def answer = bat(script: '@curl -s http://localhost:8081/add/2/3', returnStdout: true).trim()
                    echo "Smoke test: /add/2/3 answered ${answer}"
                    if (answer != '5') {
                        error "Smoke test failed: expected 5 but got ${answer}"
                    }
                }
                echo "Application deployed successfully: http://localhost:8081 (version ${VERSION})"
            }
        }

The other lines:

  • docker rm -f calc-staging: remove the previous staging container (|| true / exit /b 0 ignores the error when there is none, on the first run).
  • -d: the container runs in the background, so the pipeline continues.
  • Wait 3 seconds for Java to start, then the smoke test: it calls /add/2/3 and requires exactly 5. Docker version: grep -x 5 fails if the answer is different. Windows version: returnStdout: true gives the answer to Jenkins, .trim() removes the line ending, and error stops the stage if it is not 5 (@ stops Windows from adding the command itself to the answer). Either way, a wrong answer turns the stage red.
  • Jenkins in Docker calls host.docker.internal: for Jenkins, localhost is its own container, not your computer.
🔮 Predict first. Write your answer down before you run, then compare.
  1. You run the job twice. What happens to the first staging container?
  2. Open http://localhost:8080, then http://localhost:8081. What will each one show, and why are they different?

Run and check

  1. Run the job. Open http://localhost:8081: Calculator 1.0.N is running, with the number of the build. Then http://localhost:8081/add/2/3.
  2. Run the job again and refresh: the version changed.
  3. Check that Jenkins started the container, not you. You never typed docker run: the Deploy to staging stage did. In a terminal, run docker ps and find the line calc-staging:
    • IMAGE: calc-web:1.0.N, N = the number of your last green build;
    • CREATED: a few minutes ago, the time of that build (compare with its time in Jenkins);
    • PORTS: 0.0.0.0:8081->8080/tcp = port 8081 of your computer to port 8080 of the container.
    Run the job once more and type docker ps again: same name, but a new image tag and a new CREATED time. Jenkins replaced the container.
Terminal: list the running containers
docker ps
What you should see (your numbers differ)
CONTAINER ID   IMAGE            COMMAND                  CREATED         STATUS         PORTS                    NAMES
302a9674d125   calc-web:1.0.11  "/__cacert_entrypoin…"   7 minutes ago   Up 7 minutes   0.0.0.0:8081->8080/tcp   calc-staging
Docker Desktop also shows it in Containers, but its list does not always refresh: if calc-staging is missing there, trust docker ps. A line with 8080/tcp and no arrow (->) is a container with no port mapping: it cannot be opened in a browser.
Show the explanation
  • The second run removes the old container and starts a new one from the new image: a deployment replaces the container, the old image stays in docker images.
  • 8080 is Jenkins (its own port mapping, from Lab 1), 8081 is the calculator. Same port 8080 inside both containers, different ports on your computer: exactly the third Port Mapping slide.
💥 Break it on purpose (2 min). Put // in front of the docker rm -f calc-staging line and run the job. Read the error in the Console Output, then remove the //. (The answer goes in checkpoint 5.)
Show what happens

Conflict. The container name "/calc-staging" is already in use. Two containers cannot have the same name: the old one must be removed before the new one starts. Changing the host port would not help either: two containers on 8081 give port is already allocated.

Screenshots: the browser on http://localhost:8081 showing the version (app.png), and the output of docker ps added to docker.png.
✅ Checkpoint 5: answer in report.txt, in your own words (one or two lines each).
  1. In -p 8081:8080, which number belongs to your computer, which one to the container?
  2. What did the error say when you removed docker rm -f? What does that line do?
  3. What does the smoke test prove that the unit tests could not prove?
See the answer
  1. 8081 is the port of your computer (the browser uses it), 8080 is the port inside the container (the app listens on it). -p HOST:CONTAINER.
  2. Conflict. The container name "/calc-staging" is already in use. Two containers cannot have the same name. docker rm -f calc-staging removes the old staging container (even if it is running) before the new version starts.
  3. The unit and integration tests run the code in the Jenkins workspace. The smoke test calls the app really deployed: the image built correctly, the container started, the port mapping works, and the answer is right. Example seen in this lab: tests green, but the container crashed at start (Java 25 code in a Java 21 image). Only the smoke test caught it.
