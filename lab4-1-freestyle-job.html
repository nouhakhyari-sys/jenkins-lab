Lab 4 · Freestyle Projects and Blue Ocean

1. Your First Freestyle Job

A Freestyle project is the oldest type of Jenkins job. There is no Jenkinsfile: you configure everything with forms in the web page. You will rebuild the calculator of Lab 3 this way, so you can compare.

Step 1: Create the job

On the dashboard, click New Item, type freestyle-calculator, select Freestyle project, then OK.

Step 2: Add a parameter

  1. In General, tick This project is parameterized.
  2. Add Parameter › Boolean Parameter.
  3. Name: SIMULATE_BUG. Description: Tick to put a bug in the calculator. Leave Set by Default unticked.

Step 3: Get the code from GitHub

  1. In Source Code Management, choose Git.
  2. Repository URL: https://github.com/nouhakhyari-sys/jenkins-labs-template.git. Credentials: - none - (public repository).
  3. Branch Specifier: change */master to */main.

Step 4: Build, test and package

In Build Steps, click Add build step:

  • Docker: choose Execute shell and paste:
Execute shell (Jenkins in Docker)
cd lab2/java-app
javac -d build/classes src/Calculator.java test/CalculatorTest.java
java -DsimulateBug=$SIMULATE_BUG -cp build/classes CalculatorTest
jar cfe build/calculator.jar Calculator -C build/classes .
  • Windows: choose Execute Windows batch command and paste:
Execute Windows batch command (Jenkins on Windows)
cd lab2\java-app
javac -d build/classes src/Calculator.java test/CalculatorTest.java
java -DsimulateBug=%SIMULATE_BUG% -cp build/classes CalculatorTest
jar cfe build/calculator.jar Calculator -C build/classes .

These are the commands of the Lab 3 Jenkinsfile, in one box. $SIMULATE_BUG (Docker) and %SIMULATE_BUG% (Windows) read the value of the parameter: in a Freestyle job, parameters are environment variables.

Step 5: What to do after the build

In Post-build Actions, click Add post-build action twice:

  1. Publish JUnit test result report. Test report XMLs: lab2/java-app/build/test-results/*.xml
  2. Archive the artifacts. Files to archive: lab2/java-app/build/calculator.jar. Click Advanced and tick Fingerprint all archived artifacts.

Jenkins may show a warning under these fields, such as doesn't match anything or does not exist. This is normal before the first build: Jenkins checks the path in the workspace, which is still empty. The files will exist after the build. Click Save.

Step 6: Run it twice

  1. Click Build with Parameters, leave SIMULATE_BUG unticked, click Build. The build is green.
  2. Run it again with SIMULATE_BUG ticked. The build is yellow (UNSTABLE): the commands worked, but the JUnit report contains a failed test.
  3. On the yellow build, open Test Result: the two addition tests failed, add_2_and_3 and add_a_negative_number, because the bug adds 1 to every addition. They are marked Regression: they passed in the previous build and fail now. Take a screenshot of this page: it is part of your hand-in (freestyle.png).
  4. Open Console Output: the 4 commands, then the JUnit report and the artifact.
No Stage View here, and that is normal. A Freestyle job has no stages, only one block of commands, so Jenkins has nothing to draw in columns. Same result, different way: This job does exactly what the Lab 3 Jenkinsfile does. The difference is where the configuration lives: in forms inside Jenkins, not in a file in Git. You will compare both in part 2.
