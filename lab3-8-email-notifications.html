Lab 3 · Build a Java Project

8. Email Notifications

CI is only useful if the developer learns at once that the build broke. Nobody watches the Jenkins page all day: Jenkins sends an email. In this part you use the Email Extension plugin to send a different email for a green, a yellow and a red build.

You send the emails to Mailpit, a small test mail server. It catches every email and shows it in a web inbox at http://localhost:8025. No account, no password, nothing leaves your computer. Time: about 15 minutes.

Before you start: which Jenkins do you have?

Two values depend on how Jenkins runs on your computer. Find your column and use only its values on this page.

Step 1: Check the two plugins

In Manage Jenkins › Plugins › Installed plugins, search each name and check that its switch is blue (enabled):

  • Email Extension: sends the emails;
  • Workspace Cleanup: cleanWs() in your pipeline.

Both come with the suggested plugins of Lab 1. If one is missing or disabled, install or enable it, then restart Jenkins (http://localhost:8080/restart): a plugin is only active after a restart.

Step 2: Start the test mail server (Mailpit)

Box A · Jenkins in Docker: Mailpit joins the same network as Jenkins, which reaches it by the name mailpit
docker network create jenkins-net
docker network connect jenkins-net jenkins-local
docker run -d --name mailpit --network jenkins-net -p 8025:8025 axllent/mailpit
Box B · Jenkins installed on Windows: Mailpit publishes its mail port 1025 on localhost
docker run -d --name mailpit -p 8025:8025 -p 1025:1025 axllent/mailpit

No Docker on your Windows PC? Download mailpit for Windows from github.com/axllent/mailpit/releases, unzip it and run mailpit.exe. Keep its window open.

Check: open http://localhost:8025. You see an empty inbox. Mailpit must stay running while Jenkins sends emails; the inbox page itself can be closed.

Step 3: Configure Jenkins and send a test email

Go to Manage Jenkins › System. You fill in three sections of this long page. In each email section, the port field is hidden: click Advanced to see it.

  1. Jenkins Location: Jenkins URL = http://localhost:8080/ (it builds the links in the emails), System Admin e-mail address = jenkins@lab.local (the sender).
  2. Extended E-mail Notification (used by your pipeline): SMTP server = mailpit or localhost (see your column), Advanced › SMTP Port = 1025. Leave Credentials empty, Use SSL and Use TLS unticked.
  3. E-mail Notification (at the bottom, used by the test button): same SMTP server, Advanced › SMTP Port = 1025.
  4. Still in E-mail Notification: tick Test configuration by sending test e-mail, type me@lab.local, click Test configuration.
  5. Click Save.
Do not go further until the test works. You must see "Email was successfully sent" and the test email in Mailpit. If not, look at the troubleshooting at the bottom of this page: the cause is almost always the SMTP server (wrong column) or the port (still 25).

Step 4: Send emails from your pipeline

Open my-java-pipeline › Configure. Select everything in the Script box, delete it, and paste the script for your Jenkins. It is your pipeline of part 6, with the three email blocks marked // NEW in post. Then click Save.

my-java-pipeline with email notifications: Jenkins in Docker
pipeline {
    agent any

    options {
        timestamps()
    }

    parameters {
        booleanParam(name: 'SIMULATE_BUG', defaultValue: false,
                     description: 'Tick to put a bug in the calculator')
        choice(name: 'TARGET', choices: ['test', 'production'],
               description: 'Where to deploy')
    }

    stages {
        stage('Checkout') {
            steps {
                git branch: 'main', url: 'https://github.com/nouhakhyari-sys/jenkins-labs-template.git'
            }
        }
        stage('Build') {
            steps {
                dir('lab2/java-app') {
                    sh 'javac -d build/classes src/Calculator.java test/CalculatorTest.java'
                }
            }
        }
        stage('Test') {
            steps {
                dir('lab2/java-app') {
                    sh "java -DsimulateBug=${params.SIMULATE_BUG} -cp build/classes CalculatorTest"
                }
            }
            post {
                always {
                    junit 'lab2/java-app/build/test-results/*.xml'
                }
            }
        }
        stage('Package') {
            steps {
                dir('lab2/java-app') {
                    sh 'jar cfe build/calculator.jar Calculator -C build/classes .'
                }
                archiveArtifacts artifacts: 'lab2/java-app/build/calculator.jar', fingerprint: true
            }
        }
        stage('Deploy') {
            steps {
                input message: "Deploy calculator.jar to ${params.TARGET}?", ok: 'Deploy'
                echo "Deploying calculator.jar to ${params.TARGET}..."
            }
        }
    }

    post {
        success {                         // NEW
            emailext to: 'team@lab.local',
                     subject: "SUCCESS: ${env.JOB_NAME} #${env.BUILD_NUMBER}",
                     body: "Build passed: ${env.BUILD_URL}"
        }
        unstable {                        // NEW
            emailext to: 'team@lab.local',
                     subject: "UNSTABLE: ${env.JOB_NAME} #${env.BUILD_NUMBER}",
                     body: "Tests failed: ${env.BUILD_URL}testReport/",
                     attachLog: true
        }
        failure {                         // NEW
            emailext to: 'team@lab.local',
                     subject: "FAILURE: ${env.JOB_NAME} #${env.BUILD_NUMBER}",
                     body: "Build broken: ${env.BUILD_URL}console",
                     attachLog: true
        }
        always {
            cleanWs()
        }
    }
}

Did part 7 (AnsiColor)? Add ansiColor('xterm') back under timestamps() in options.
  • success, unstable, failure: one email per result, each with its own subject.
  • emailext is the step of the Email Extension plugin: to the recipients (any address works with Mailpit), subject and body the text, attachLog: true attaches the Console Output to the email.
  • env.JOB_NAME, env.BUILD_NUMBER and env.BUILD_URL are filled in by Jenkins: double quotes are needed.
  • always { cleanWs() } is unchanged. The emails do not need the workspace: attachLog sends the build log, which Jenkins keeps.

Step 5: Test the emails

  1. Build with Parameters, SIMULATE_BUG unticked, approve the Deploy: Mailpit shows SUCCESS: my-java-pipeline #….
  2. Build with Parameters, SIMULATE_BUG ticked, approve: the email UNSTABLE: my-java-pipeline #… arrives, with build.log attached. Click the link in the email: it opens the test report.

In Console Output, the line Sending email to: team@lab.local shows that Jenkins handed the email to the SMTP server.

In a real team, the email goes to the developers whose commits are in the build: add recipientProviders: [developers(), requestor()] to emailext. Jenkins uses the company mail server instead of Mailpit, and many teams also send alerts to Slack or Teams.

Troubleshooting

The build is green, the log says "Sending email to", but Mailpit is empty

Jenkins sent the email to another server. Check Extended E-mail Notification:

  • SMTP server: localhost if Jenkins is installed on Windows, mailpit only if Jenkins runs in Docker. Using mailpit on a Windows Jenkins is the most common mistake.
  • Advanced › SMTP Port: 1025, not 25.

Still nothing? Tick Enable Debug Mode in the same section, save, build again: the Console Output shows DEBUG SMTP: trying to connect to host "…", port …, the server Jenkins really uses. Untick it afterwards.

Test button: "Failed to send out e-mail … port: 25 …"

The SMTP Port of E-mail Notification is still 25. Click Advanced in that section, set 1025, test again.

Test button: "Unknown host" or "Connection refused"

Wrong SMTP server for your Jenkins (see your column), or Mailpit is not running: docker ps must list mailpit. For a Windows Jenkins, its line must show 0.0.0.0:1025->1025/tcp; if not, run docker rm -f mailpit, then the command of box B again.

Error "No such DSL method 'cleanWs'" (build red at the end)

The Workspace Cleanup plugin is disabled or missing. Enable or install it in Installed plugins / Available plugins, then restart Jenkins. Check: Pipeline Syntax › Sample Step lists cleanWs.

Error "No such DSL method 'emailext'"

The Email Extension plugin is disabled or missing. Enable or install it, restart Jenkins, build again.

Error "No such DSL method 'post'" … WorkflowScript:1

The Script box contains only the post block. Replace the whole content of the Script box with the complete script of step 4.

The links in the email contain "null"

The Jenkins URL is not set: Manage Jenkins › System › Jenkins Location, type http://localhost:8080/, save.

Mailpit shows no inbox at localhost:8025

Mailpit is not running: docker ps must list mailpit. If it stopped, run docker start mailpit (or open mailpit.exe again).
