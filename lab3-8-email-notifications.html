Lab 3 · Build a Java Project

8. Email Notifications

CI is only useful if the developer learns at once that the build broke. Nobody watches the Jenkins page all day: Jenkins sends an email. In this part you use the Email Extension plugin to send a different email for a green, a yellow and a red build.

To avoid problems with real mailboxes (passwords, school network), you send the emails to Mailpit, a small test mail server. It catches every email and shows it in a web inbox at http://localhost:8025. Nothing leaves your computer. Time: about 15 minutes.

Step 1: Check the plugin

  1. Manage Jenkins › Plugins › Installed plugins, search Email Extension.
  2. It is normally there: the setup wizard installed it with the suggested plugins. If not, install it from Available plugins (as in Lab 2, page 0), then restart Jenkins (http://localhost:8080/restart).

Step 2: Start the test mail server (Mailpit)

Jenkins in Docker: Jenkins and Mailpit run in two containers. Put them on the same Docker network so that Jenkins can reach Mailpit by its name, mailpit. Run these three commands in a terminal:

Jenkins in Docker: start Mailpit next to Jenkins
docker network create jenkins-net
docker network connect jenkins-net jenkins-local
docker run -d --name mailpit --network jenkins-net -p 8025:8025 axllent/mailpit

Jenkins installed on Windows (with Docker Desktop): Jenkins reaches Mailpit on localhost, so publish the mail port too:

Jenkins installed on Windows: start Mailpit
docker run -d --name mailpit -p 8025:8025 -p 1025:1025 axllent/mailpit

No Docker on your Windows PC? Download mailpit for Windows from github.com/axllent/mailpit/releases, unzip it and run mailpit.exe.

Check: open http://localhost:8025. You see an empty inbox.

Step 3: Configure Jenkins

Go to Manage Jenkins › System and fill in two sections:

  1. Jenkins Location: check that Jenkins URL is http://localhost:8080/ (it builds the links in the emails), and set System Admin e-mail address to jenkins@lab.local. This is the sender of every email.
  2. Extended E-mail Notification:
    • SMTP server: mailpit (Jenkins in Docker) or localhost (Jenkins on Windows);
    • SMTP Port: 1025;
    • if these fields are hidden, click Advanced; leave Credentials empty and Use SSL and Use TLS unticked: Mailpit needs no password.
  3. Click Save.
Optional: send a test email from the configuration page

The test button is in the other email section, E-mail Notification (Mailer plugin), at the bottom of the same page. Set its SMTP server and port the same way (under Advanced: SMTP Port 1025), tick Test configuration by sending test e-mail, type me@lab.local and click Test configuration. The message "Email was successfully sent" appears, and the email is in Mailpit.

Step 4: Send emails from your pipeline

Open my-java-pipeline › Configure. Replace the whole post { … } block at the end of the pipeline (the one with cleanWs()) by this one. It is the same in Docker and Windows:

post block with one email per result
    post {
        success {
            emailext to: 'team@lab.local',
                     subject: "SUCCESS: ${env.JOB_NAME} #${env.BUILD_NUMBER}",
                     body: "Build passed: ${env.BUILD_URL}"
        }
        unstable {
            emailext to: 'team@lab.local',
                     subject: "UNSTABLE: ${env.JOB_NAME} #${env.BUILD_NUMBER}",
                     body: "Tests failed: ${env.BUILD_URL}testReport/",
                     attachLog: true
        }
        failure {
            emailext to: 'team@lab.local',
                     subject: "FAILURE: ${env.JOB_NAME} #${env.BUILD_NUMBER}",
                     body: "Build broken: ${env.BUILD_URL}console",
                     attachLog: true
        }
        cleanup {
            cleanWs()
        }
    }
  • success, unstable, failure: one email per result, each with its own subject.
  • emailext is the step of the Email Extension plugin: to the recipients (separate several with commas), subject and body the text, attachLog: true attaches the Console Output to the email.
  • env.JOB_NAME, env.BUILD_NUMBER and env.BUILD_URL are filled in by Jenkins: double quotes are needed.
  • cleanup runs last, after the emails. cleanWs() moved there so the workspace is deleted only when everything else is done.

Step 5: Test the three emails

  1. Build with Parameters, SIMULATE_BUG unticked, approve the Deploy: Mailpit shows SUCCESS: my-java-pipeline #….
  2. Build with Parameters, SIMULATE_BUG ticked, approve: the email UNSTABLE: my-java-pipeline #… arrives, with build.log attached. Click the link in the email: it opens the test report.
  3. Optional, a red build: in Configure, change src/Calculator.java into src/Calculatr.java in the Build stage, build: email FAILURE. Then put the right name back.

In Console Output, the line Sending email to: team@lab.local shows that Jenkins sent the email.

In a real team, the email goes to the developers whose commits are in the build: add recipientProviders: [developers(), requestor()] to emailext. Many teams send failures only, or use Slack or Teams plugins instead of email, so the alerts are not ignored.
Option: send a real email with Gmail

Only if your school network allows it. Gmail needs an app password, never your real password:

  1. In your Google Account, turn on 2-Step Verification, then open Security › App passwords, create one named jenkins and copy the 16 characters.
  2. In Jenkins: Manage Jenkins › Credentials › add Username with password: username = your Gmail address, password = the app password, ID gmail.
  3. In Extended E-mail Notification: SMTP server smtp.gmail.com, SMTP Port 465, Credentials gmail, tick Use SSL. Set System Admin e-mail address to the same Gmail address.
  4. In the pipeline, replace team@lab.local by your own address.

If the build log shows 535 Authentication failed, the app password is wrong; Connection timed out means the network blocks the mail port: go back to Mailpit.

Troubleshooting

Error "No such DSL method 'emailext'"

The Email Extension plugin is missing or disabled. Install or enable it, restart Jenkins, build again.

The build is green but nothing arrives in Mailpit

Read the Console Output. Connection refused or Couldn't connect to host: wrong SMTP server or port. Jenkins in Docker: server mailpit, and check that both containers are on the network with docker network inspect jenkins-net. Jenkins on Windows: server localhost, port 1025, and Mailpit started with -p 1025:1025.

"An attempt to send an e-mail to empty list of recipients, ignored"

The to: line is missing or empty in emailext.

The links in the email contain "null"

The Jenkins URL is not set: Manage Jenkins › System › Jenkins Location, type http://localhost:8080/, save.

Mailpit shows no inbox at localhost:8025

The container is not running: docker ps must list mailpit. If it stopped, run docker start mailpit.
