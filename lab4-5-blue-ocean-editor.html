Lab 4 · Freestyle Projects and Blue Ocean

5. The Blue Ocean Editor

Blue Ocean can create a pipeline with buttons. When you save, it writes a Jenkinsfile and commits it to your GitHub repository. You will create a pipeline for your own jenkins-labs repository, with two stages that run in parallel.

Step 1: Create a GitHub token (classic)

Blue Ocean needs a token to read your private repository and to save the Jenkinsfile in it. It only accepts classic tokens.

  1. On GitHub: your photo (top right) › Settings › Developer settings › Personal access tokens › Tokens (classic) › Generate new token › Generate new token (classic).
  2. Check that the page title is New personal access token (classic). If you see sections called Repository access and Permissions, you are on the fine-grained token page: Blue Ocean does not accept those tokens. Go back and choose Tokens (classic), or open https://github.com/settings/tokens/new.
  3. Note: blue-ocean-lab. Expiration: 7 days.
  4. Tick the scopes repo, and under user: read:user and user:email.
  5. Click Generate token and copy it now: GitHub shows it only once.

Step 2: Connect Blue Ocean to your repository

  1. In Blue Ocean, click New Pipeline.
  2. Where do you store your code? GitHub.
  3. Paste your token in the field and click Connect.
  4. Choose your GitHub account, then your jenkins-labs repository, and click Create Pipeline.
  5. Your repository has no Jenkinsfile at its root, so Blue Ocean opens the editor to create one.

Step 3: Give your token to the new job (before you save)

Blue Ocean uses your token to save the Jenkinsfile, but it does not give it to the job that reads your repository. Your repository is private, so without this step Jenkins cannot see it, and saving ends with Indexing failed. Do it now, in a second browser tab, and keep the editor open in the first one:

  1. Open a new tab on http://localhost:8080. On the dashboard, a new job named after your repository appeared: open it and click Configure.
  2. In Branch Sources, block GitHub, the Credentials box is empty (warning Credentials are recommended). Click + Add › Jenkins: Kind Username with password, Username: your GitHub username, Password: your token (ghp_…), ID: github-token. Click Add.
  3. Select the new entry in the Credentials list (adding it does not select it).
  4. Click Validate under the repository URL: the answer must be Credentials ok. Then Save, and go back to the editor tab.

Step 4: Build the pipeline with buttons

First, get the project. Your repository holds your hand-in files, not the Java project. So, like any real pipeline, the first stage starts with a checkout: it clones the calculator project into your workspace, in a folder calc, then compiles it. The next stages work in calc/lab2/java-app.

The editor has two areas. In the middle, the graph of your pipeline: a Start circle and a + circle after it. On the right, a panel with the settings of what you selected. You add stages with the + circles in the graph; you fill them in the right panel. First, in the right panel (Pipeline Settings), keep Agent: any. Then:

  1. In the graph, click the + circle just after Start. A new stage appears; in the right panel, name it Build. Still in the right panel, click + Add step and choose Shell Script (Docker) or Windows Batch Script (Windows). The Script box has only one line: paste the whole command below (it is one long line), then go back with the arrow at the top of the panel.
Build: Shell Script (Docker), one line
rm -rf calc && git clone --depth 1 https://github.com/nouhakhyari-sys/jenkins-labs-template.git calc && cd calc/lab2/java-app && javac -d build/classes src/Calculator.java test/CalculatorTest.java
Build: Windows Batch Script (Windows), one line
(if exist calc rmdir /s /q calc) & git clone --depth 1 https://github.com/nouhakhyari-sys/jenkins-labs-template.git calc && cd calc\lab2\java-app && javac -d build/classes src/Calculator.java test/CalculatorTest.java
  1. Click the + after Build, name the stage Test. Add a script step with the command below, then a second step: search junit in the list of steps, choose Archive JUnit-formatted test results (not the "Open Test Reporting" one), and in TestResults give the path calc/lab2/java-app/build/test-results/*.xml.
Test: Shell Script (Docker)
cd calc/lab2/java-app && java -cp build/classes CalculatorTest
Test: Windows Batch Script (Windows)
cd calc\lab2\java-app && java -cp build/classes CalculatorTest
  1. Click the + under the Test circle: this adds a stage in parallel. Name it Java version, add a script step with java -version (same command in Docker and Windows).
  2. Click the + after Test, name the stage Package. Add a script step with the command below, then a step Archive the artifacts with calc/lab2/java-app/build/calculator.jar.
Package: Shell Script (Docker)
cd calc/lab2/java-app && jar cfe build/calculator.jar Calculator -C build/classes .
Package: Windows Batch Script (Windows)
cd calc\lab2\java-app && jar cfe build/calculator.jar Calculator -C build/classes .
See the code behind the buttons: in the editor, press Ctrl + S (Mac: Cmd + S). Blue Ocean shows the Jenkinsfile it is writing. You can even edit it there and click Update.

Step 5: Save and run

  1. Click Save (top right). Description: Pipeline created with Blue Ocean. Keep Commit to main. Click Save & run once.
  2. Blue Ocean commits the Jenkinsfile to your repository and starts a run. An error appears instead? Do not click Save & run again: your Jenkinsfile is probably already saved, and a second save fails with error 422. Click Cancel, check that the Jenkinsfile is on GitHub, then open your job in the classic interface and click Scan Repository Now. If the scan log says anonymous access, step 3 was missed: do it now.
  3. Blue Ocean usually updates the page by itself; if a run seems stuck or does not appear, refresh the page (F5).
  4. When the run starts, look at the graph: Test and Java version appear one above the other: they run at the same time.
  5. When the run is green, take a screenshot of it in Blue Ocean, with the parallel stages visible: it is part of your hand-in (blueocean.png).

Step 6: Look at GitHub

Open your jenkins-labs repository on GitHub: a new Jenkinsfile is at its root, in a commit with your description. Open it. It is a normal declarative pipeline, like the ones you wrote by hand; the parallel stages are in a parallel { } block.

Show the expected Jenkinsfile (Docker version; it can look slightly different)
pipeline {
  agent any
  stages {
    stage('Build') {
      steps {
        sh 'rm -rf calc && git clone --depth 1 https://github.com/nouhakhyari-sys/jenkins-labs-template.git calc && cd calc/lab2/java-app && javac -d build/classes src/Calculator.java test/CalculatorTest.java'
      }
    }
    stage('Test') {
      parallel {
        stage('Test') {
          steps {
            sh 'cd calc/lab2/java-app && java -cp build/classes CalculatorTest'
            junit 'calc/lab2/java-app/build/test-results/*.xml'
          }
        }
        stage('Java version') {
          steps {
            sh 'java -version'
          }
        }
      }
    }
    stage('Package') {
      steps {
        sh 'cd calc/lab2/java-app && jar cfe build/calculator.jar Calculator -C build/classes .'
        archiveArtifacts 'calc/lab2/java-app/build/calculator.jar'
      }
    }
  }
}

On Windows, every sh is a bat.

What Blue Ocean created in Jenkins is a multibranch pipeline named after your repository: Jenkins scans every branch of the repository and runs each branch that contains a Jenkinsfile.
