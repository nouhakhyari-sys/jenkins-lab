8. Checklist and Help

Checklist

Required (parts 1 to 5):

  • ☐ docker-check shows a Client and a Server.
  • ☐ calc-web: two test stages in parallel, 7 tests, green.
  • ☐ With SIMULATE_BUG: yellow, and the Docker stages are skipped.
  • ☐ docker images calc-web lists one tag per build.
  • ☐ http://localhost:8081 shows the version of the last build.
  • ☐ report.txt: checkpoints 1 to 5 answered.

Bonus:

  • ☐ Part 6: with DEPLOY_ENV = production and the approval, http://localhost:8082 shows the same version; checkpoint 6 answered.
  • ☐ One or more challenges of part 7 (push, scan, rollback).

Hand in your work

In the lab5 folder of your jenkins-labs repository (no lab5 folder? Add file › Create new file, name lab5/README.md, guide: How to hand in your work):

  • report.txt: the template below, filled in. It counts most: short answers in your own words, not copied from this site;
  • Jenkinsfile: your final script;
  • order.png: the table of part 2 after Check my answers, with your score;
  • stages.png: the Blue Ocean graph with the two test branches in parallel;
  • artifacts.png: the build page with calculator-web.jar and image.txt;
  • docker.png: the terminal with docker images calc-web and docker ps;
  • app.png: the browser on http://localhost:8081 (or 8082);
  • bonus: challenge.png, a screenshot proving each challenge you did (your Docker Hub tags, the scan stage, or production back to an old version).

Troubleshooting

"docker: not found" (Jenkins in Docker)

Jenkins still runs the old image. Run docker ps: the IMAGE of your Jenkins container must be jenkins-docker. Redo part 1, path B, from B3.

"permission denied while trying to connect to the Docker daemon socket"

The container was started without -u root, or without -v /var/run/docker.sock:/var/run/docker.sock. Run docker rm -f jenkins-local, then the docker run line of part 1 (B5) with your volume or folder: your jobs are safe in it.

"'docker' is not recognized" (Jenkins on Windows)

Docker Desktop is not installed, or Jenkins was started before it. Start Docker Desktop, then stop Jenkins (Ctrl + C) and start it again from a new Command Prompt. Still failing: Manage Jenkins › System › Global properties › Environment variables, add PATH+DOCKER = C:\Program Files\Docker\Docker\resources\bin.

"error during connect" / "Cannot connect to the Docker daemon"

Docker Desktop is not running. Start it, wait for Engine running, and run the job again.

Docker image: "invalid reference format"

A blank is still in the docker build line (____), or a variable is misspelled. The tag must look like calc-web:1.0.12. Compare with the solution of part 4.

Docker image: "COPY failed: file not found … calculator-web.jar"

The Docker image stage ran before the jar was created, or the Package stage changed its name. The order must be Build → Tests → Package → Docker image, and the jar must be build/calculator-web.jar.

Staging: the container stops at once, and the smoke test fails ("Connection refused")

Run docker logs calc-staging. If it says UnsupportedClassVersionError … class file version 69.0 … up to 65.0: Jenkins compiled the code with a newer Java (25) than the one in the image (21). The Build stage must use javac --release 21: check your script. This is the it works on my machine problem, caught by the pipeline before production.

Deploy: "port is already allocated"

Another program or container already uses 8081 (or 8082). Find it with docker ps and remove it (docker rm -f <name>), or change the host port in the script (for example -p 8091:8080, and the same port in the smoke test).

The smoke test fails, but the browser shows the app

The app needed more than 3 seconds to start: wait longer (sleep 6, or ping -n 7 127.0.0.1 >nul on Windows). Jenkins in Docker: check that the container was started with --add-host=host.docker.internal:host-gateway, and that the smoke test uses host.docker.internal, not localhost.

Challenge 1: "access token has insufficient scopes"

Login Succeeded, but the push fails: the Docker Hub token is read-only. On Docker Hub, Account settings › Personal access tokens › Generate new token with Read & Write. In Jenkins, Manage Jenkins › Credentials, click your Docker Hub credential › Update, paste the new token as the password, Save, and run again.

Challenge 1: "Could not find credentials entry with ID dockerhub"

This Jenkins has no credential with the ID dockerhub: it was created with another ID, in another Jenkins, or not in System › Global credentials. Create it again there with ID exactly dockerhub (an ID cannot be changed later), or put the existing ID in credentialsId: of the script.

Challenge 1: "denied: requested access to the resource is denied"

The login failed or the image name does not start with your Docker Hub username. Check the credential dockerhub (username, and a token with Read & Write), and the docker tag line.

Challenge 2: "manifest unknown" for the Trivy image

That Trivy version is not on Docker Hub. Open hub.docker.com/r/aquasec/trivy/tags, choose a recent version number (not latest), and use it in the stage.

The Docker stages are always skipped

The build is not green: a test failed (SIMULATE_BUG ticked?). Look at Test Result. This is on purpose: a yellow build must not be deployed.
