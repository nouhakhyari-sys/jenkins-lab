Lab 2 · Your First Pipeline

5. Your Turn: Exercises

Create a new Pipeline job called my-first-pipeline and complete the exercises in order. Try first, then open the solution to check.

Exercise 1: Three stages

Write a pipeline with three stages: Build, Test and Deploy. Each stage prints a message with echo. Build it and look at the stages: you now see the pipeline from the course, Build → Test → Deploy.

Show the solution of exercise 1

Three stage blocks inside stages, one after the other:

pipeline {
    agent any
    stages {
        stage('Build') {
            steps {
                echo 'Building the application...'
            }
        }
        stage('Test') {
            steps {
                echo 'Running the tests...'
            }
        }
        stage('Deploy') {
            steps {
                echo 'Deploying to staging...'
            }
        }
    }
}

Exercise 2: Break it, then fix it with Replay

  1. In the Test stage, add a command that fails: sh 'exit 1' (any command that returns an error code makes the build fail).
  2. Save and build. The build turns red.
  3. Open the Console Output and find the error message. What happened to the Deploy stage?
  4. Fix it with Replay: remove the failing line and click Run. The new build is green.
Show the answer of exercise 2

The log shows ERROR: script returned exit code 1 and ends with Finished: FAILURE. The Deploy stage did not run: Jenkins skips the next stages after a failure ("skipped due to earlier failure(s)"). This is the "stop the line" principle from the course: a failing stage stops the change.

Note: Replay fixed this run only. The job script still contains exit 1; remove it with Configure too.

Exercise 3: Jenkins variables

Jenkins provides variables about each build. Run this pipeline twice and compare the output of the two builds:

Print the job name and build number
pipeline {
    agent any
    stages {
        stage('Info') {
            steps {
                echo "Job name: ${env.JOB_NAME}"
                echo "Build number: ${env.BUILD_NUMBER}"
                echo 'Single quotes: ${env.BUILD_NUMBER}'
            }
        }
    }
}
Show the answer of exercise 3

The build number changes at each build (1, then 2…). The third line prints ${env.BUILD_NUMBER} literally: with single quotes, variables are not replaced. Use double quotes when a text contains a variable.

Bonus: what happens after the stages?

The post block runs after all stages, depending on the result. Run this pipeline, then add sh 'exit 1' in the Test stage and run it again. Which messages appear each time?

Messages after a success or a failure
pipeline {
    agent any
    stages {
        stage('Test') {
            steps {
                echo 'Running the tests...'
            }
        }
    }
    post {
        success {
            echo 'The pipeline succeeded.'
        }
        failure {
            echo 'The pipeline failed. Read the logs above.'
        }
        always {
            echo 'This message is always printed.'
        }
    }
}
Show the answer of the bonus

When the build succeeds: "The pipeline succeeded." and "This message is always printed." When it fails: "The pipeline failed…" and "This message is always printed." In real projects, post is used to send notifications (email, Slack) and clean up.
