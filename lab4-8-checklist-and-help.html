Lab 4 · Freestyle Projects and Blue Ocean

8. Checklist and Help

Checklist

  • ☐ freestyle-calculator: one green build and one yellow build with SIMULATE_BUG.
  • ☐ freestyle-deploy starts after a green build, not after a yellow one.
  • ☐ config.txt filled in from the config.xml of my two jobs.
  • ☐ Blue Ocean installed; blueocean.txt filled in from my run with the bug.
  • ☐ A pipeline created with the Blue Ocean editor, with parallel stages, green, and its Jenkinsfile on GitHub.
  • ☐ A branch feature/hello and its pull request built automatically, then merged.
  • ☐ I opened a run in Pipeline Overview.

Hand in your work

In your jenkins-labs repository (guide: How to hand in your work). No lab4 folder? Create it: Add file › Create new file, type lab4/README.md as the name, write Lab 4, Commit changes. Then upload into lab4:

  • lab4/freestyle.png: the Test Result page of the yellow freestyle-calculator build;
  • lab4/config.txt: the 8 answers of part 2, exercise B;
  • lab4/blueocean.txt and lab4/blueocean-tests.png: part 4, your run with the bug;
  • lab4/blueocean.png: your Blue Ocean run with the parallel stages;
  • lab4/pull-request.png: the Pull Requests tab in Blue Ocean with your built pull request;
  • the Jenkinsfile at the root of the repository: Blue Ocean already committed it for you.

In the commit message of your screenshots, answer: when would you choose a Freestyle job instead of a pipeline?

Troubleshooting

Freestyle: "Couldn't find any revision to build"

Branch Specifier is still */master. Change it to */main.

Freestyle: "javac: not found" (Docker) or "'javac' is not recognized" (Windows)

Same fix as in Lab 3. Docker: use the image jenkins/jenkins:lts-jdk21. Windows: install a JDK 21 (not only a JRE), add it to the PATH, restart Jenkins.

Freestyle: "No test report files were found"

Check the path in Publish JUnit test result report: lab2/java-app/build/test-results/*.xml. If the build failed before the tests ran (red), fix the build step first: the report does not exist.

Freestyle on Windows: "'cd' ... the system cannot find the path" or the commands run in the wrong folder

Use a backslash: cd lab2\java-app, and the Execute Windows batch command step, not Execute shell.

"Blue Ocean" is not in Available plugins

Click Advanced settings (in Plugins) and then Check now to refresh the list, and search again. If it is still missing, it may already be installed: look in Installed plugins. Otherwise call the teacher.

No "Open Blue Ocean" in the menu

Normal on recent Jenkins versions: open http://localhost:8080/blue directly. If this address gives a 404 error, Jenkins was not restarted after the installation: restart it (part 3, step 2).

Blue Ocean refuses the token, or my repository is not in the list

Use a classic token (not fine-grained) with the scopes repo, read:user and user:email. Check that you chose your own account as the organisation. Copy the token again: it must have no space before or after.

Blue Ocean: "Error Indexing failed" when I click Save &amp; run

Open your repository on GitHub. If the Jenkinsfile is there (commit Added Jenkinsfile), the save worked: only the scan that follows failed. Click Cancel, go to the classic interface, open the job named after your repository, and click Scan Repository Now. If the scan log says anonymous access, see the next item. The main branch appears and its first run starts. If the scan fails again, open Scan Repository Log: the last lines give the reason.

Scan log: "Invalid scan credentials when using anonymous access"

Jenkins tries to read your private repository without your token. Give it the token:

  1. In the classic interface, open the job named after your repository and click Configure.
  2. In Branch Sources, block GitHub, the Credentials list is empty. Open it and choose your token if it is there (Blue Ocean may have saved it with the ID github).
  3. Not in the list? Click Add › Jenkins. Kind: Username with password. Username: your GitHub username. Password: your classic token (ghp_…). ID: github-token. Click Add, then choose it in the list.
  4. Click Validate under the repository URL: it must answer Credentials ok. Then Save and Scan Repository Now.
Blue Ocean: error 422 "sha wasn't supplied" when I save

The Jenkinsfile is already in your repository (your first save worked), and this window tries to create it a second time. Click Cancel. Your pipeline is safe on GitHub. To change it later, open the pipeline in Blue Ocean and click the pencil icon (Edit): that editor knows the existing file and saves a new version of it.

Blue Ocean: the Build stage fails with a strange error after pasting

The Script box keeps one line only: if you pasted several lines, they were glued together. Clear the box and paste the one-line command of part 5 again.

Blue Ocean: "git: not found" or "'git' is not recognized"

The Build stage uses the git command. Docker: the Jenkins image contains it. Windows: install Git for Windows (as in Lab 3), then restart Jenkins.

Blue Ocean on Windows: "Cannot run program "sh""

You chose Shell Script. On Jenkins for Windows, use Windows Batch Script. In Blue Ocean, open the pipeline, click the pencil icon (Edit), change the steps, and save again.

My pull request does not appear in Blue Ocean

Wait for the next scan (1 minute), or in the classic interface open your repository job and click Scan Repository Now. Check that the pull request goes from feature/hello into main of your repository, not into the teacher's template.

No "Periodically if not otherwise run" option

Open the job named after your repository › Configure › Scan Repository Triggers (left menu). You can always click Scan Repository Now by hand.

No "Pipeline Overview" in the menu

Open a build (click its number, for example #7), not the job page. If it is still missing, install the Pipeline Graph View plugin.
