Lab 5 · Deploy with Docker

1. Give Jenkins Access to Docker

🎯 Why this step? Jenkins never builds anything itself: it runs commands on its machine, like javac in Lab 3. To run docker build and docker run, that machine needs the Docker client (the docker command) and a Docker engine to talk to (slide Docker Architecture: client, Docker host, registry).

Before anything: start Docker Desktop

Start Docker Desktop and look at the bottom left of its window: wait until it says Engine running (green dot). This is the Docker engine, ready to receive commands. You do not need any container yet: the Containers list can be empty. Your pipeline will create the calculator containers itself.

Then follow one path only, the one of the Jenkins you have used since Lab 1:

Your JenkinsFollowScripts of this lab
Installed on Windows (java -jar jenkins.war or start-jenkins.bat)Path A (2 minutes)bat
In a Docker containerPath B (10 minutes)sh
Ports of this lab. Jenkins: 8080. The calculator: 8081 (staging) and 8082 (production). Jenkins must not use 8081 or 8082. Run only one Jenkins at a time.

Path A: Jenkins installed on Windows

  1. Docker Desktop shows Engine running.
  2. Start Jenkins as usual. A program reads the list of commands it knows (the PATH) when it starts: if Jenkins was already running before Docker Desktop was installed, stop it (Ctrl + C) and start it again from a new Command Prompt.
  3. Create a Pipeline job named docker-check with this script, and run it:
docker-check (Jenkins on Windows)
pipeline {
    agent any
    stages {
        stage('Docker') {
            steps {
                bat 'docker version'
            }
        }
    }
}

The Console Output must show a Client part (the docker command) and a Server part (the engine it reached). Done: go to part 2.

"'docker' is not recognized as an internal or external command"

Jenkins does not know where the docker command is.

  1. Open a new Command Prompt and type docker version. If it fails there too, restart the PC (or reinstall Docker Desktop).
  2. If it works in the Command Prompt: restart Jenkins from a new Command Prompt.
  3. Still failing? Manage Jenkins › System › Global properties, tick Environment variables, Add: name PATH+DOCKER, value C:\Program Files\Docker\Docker\resources\bin. Save and run docker-check again.

Jenkins installed as a Windows service (it starts alone with Windows) may also get Access is denied: stop the service and start Jenkins from a Command Prompt instead.

Path B: Jenkins in Docker

Your Jenkins runs in a container made from the official image jenkins/jenkins. In this path you will:

  1. see the problem: that image has no docker command;
  2. build your own Jenkins image that has it;
  3. replace your container with a new one, keeping your jobs.

All the commands go in PowerShell: the Terminal button at the bottom right of Docker Desktop, or Windows + R › powershell. Use the same window from B3 to B5: the commands share variables.

B1. Find your Jenkins container

PowerShell
docker ps -a

Find the line whose IMAGE starts with jenkins/jenkins. Note its NAMES (Lab 1: jenkins-local) and its PORTS: the number on the left of ->8080 is the port of your browser.

⚠️ A Jenkins container with a random name (like zealous_feynman) and no PORTS was started with the Run button of Docker Desktop. It cannot be opened in a browser and has none of your jobs: delete it (red bin in Docker Desktop, or docker rm -f <name>). Only keep the Jenkins container you used in the previous labs.

B2. See the problem

Open your Jenkins, create a Pipeline job named docker-check with this script, and run it:

docker-check (Jenkins in Docker)
pipeline {
    agent any
    stages {
        stage('Docker') {
            steps {
                sh 'docker version'
            }
        }
    }
}

The build is red, with docker: not found. Two reasons:

  • the image jenkins/jenkins contains Jenkins and Java, but not the docker command;
  • a container is isolated (slide Docker Container Isolation): even if Docker Desktop runs on your PC, Jenkins inside its container cannot see it.

Keep this job: you will run it again at the end.

B3. Read where your container keeps its data

Paste this in PowerShell. If your container is not named jenkins-local, change the first line.

PowerShell
$old  = "jenkins-local"
$info = (docker inspect $old | Out-String | ConvertFrom-Json)[0]
$img  = $info.Config.Image
$m    = $info.Mounts | Where-Object { $_.Destination -eq "/var/jenkins_home" }
if ($m.Type -eq "volume") { $data = $m.Name } else { $data = $m.Source }
"Container: $old   Image: $img   Jenkins data: $data"

The last line shows, for example, Image: jenkins/jenkins:lts-jdk21 Jenkins data: jenkinsvol. Your jobs are not in the container: they are in a volume (a name like jenkinsvol) or in a folder of your PC (like C:\jendoc, a bind mount). Slide Manage Data in Docker.

⚠️ Jenkins data is empty? Stop here and call the teacher: deleting the container now would delete your jobs.
🔮 Predict first. Write your answer down before you run, then compare.
  1. In B5 you delete the Jenkins container. Will your jobs of Labs 1 to 4 survive? Why?

B4. Build your own Jenkins image

In the same PowerShell window, paste this block. It creates a folder jenkins-docker in your user folder, writes a Dockerfile in it, shows it, then builds the image.

PowerShell
mkdir "$HOME\jenkins-docker" -Force | Out-Null
cd "$HOME\jenkins-docker"
@"
FROM $img
USER root
COPY --from=docker:29-cli /usr/local/bin/docker /usr/local/bin/docker
"@ | Set-Content -Encoding ascii Dockerfile
Get-Content Dockerfile
docker build -t jenkins-docker .

The Dockerfile it wrote (shown by Get-Content) has three lines:

  • FROM …: start from the same Jenkins image as your current container (read in B3), so Jenkins opens your jobs without problems;
  • USER root: the next line needs the administrator account;
  • COPY --from=docker:29-cli …: take the docker program from the official Docker image and copy it into yours.

This is an image as code (slide Docker Image Creation Using a Dockerfile). The build ends with naming to docker.io/library/jenkins-docker.

B5. Replace your container

Still in the same window: delete the old container, then start the new one from your image, with your data.

PowerShell
docker rm -f $old
docker run -d --name jenkins-local -u root -p 8080:8080 -p 50000:50000 -v "${data}:/var/jenkins_home" -v /var/run/docker.sock:/var/run/docker.sock --add-host=host.docker.internal:host-gateway jenkins-docker

The last command prints a long ID. What each option does:

OptionWhat it doesSlide
-v "${data}:/var/jenkins_home"Your volume or your folder, read in B3: the new Jenkins finds the same jobs.Manage Data
-v /var/run/docker.sock:/var/run/docker.sockA bind mount of the Docker engine's socket: the docker command inside Jenkins talks to the engine of your PC. The images and containers Jenkins creates appear in your Docker Desktop.Architecture, Manage Data
-u rootJenkins runs as root, so it may use that socket.
-p 8080:8080Jenkins on http://localhost:8080.Port Mapping
--add-host=host.docker.internal:host-gatewayGives Jenkins a name for your PC, to call the calculator in the smoke test of part 5.Port Mapping

B6. Check

PowerShell
docker ps --filter name=jenkins-local

You must see IMAGE jenkins-docker, STATUS Up … and PORTS 0.0.0.0:8080->8080/tcp. (The Docker Desktop list may need a few seconds to refresh: trust this command.)

  1. Wait 30 seconds, open http://localhost:8080 and log in: your jobs are there. Was your prediction right?
  2. Run docker-check again: now the Console Output shows Client and Server.
Lab only. Giving a container the Docker socket and the root user gives it full control of the machine. It is fine on your laptop for a lab; on a shared server, teams use dedicated build agents instead.
B5 says "Conflict. The container name /jenkins-local is already in use"

A jenkins-local container already exists, maybe from a first try. Run docker ps -a --filter name=jenkins-local. IMAGE jenkins-docker and STATUS Up: it is your new Jenkins, go to B6. Otherwise: docker rm -f jenkins-local and run the docker run line of B5 again.

B5 says "port is already allocated"

Something else uses port 8080, often Jenkins installed on Windows. Stop it (Ctrl + C in its window), then docker rm -f jenkins-local and run the docker run line of B5 again.

I closed PowerShell between B3 and B5

The variables $old, $img and $data are lost. If the old container still exists, paste B3 again. If you already deleted it, write the values yourself in the docker run line: your volume name (docker volume ls) or your folder, for example -v C:\jendoc:/var/jenkins_home.

Jenkins opens, but it asks to unlock it and my jobs are gone

The new container did not get your data: $data was empty or wrong. Your jobs are still in the old volume or folder. Find it (docker volume ls, or your folder), then docker rm -f jenkins-local and run the docker run line of B5 again with -v YOUR_VOLUME_OR_FOLDER:/var/jenkins_home.

You connected Jenkins to the network jenkins-net in Lab 3 (Mailpit)?

Add --network jenkins-net to the docker run line of B5, before jenkins-docker.

On macOS or Linux (bash instead of PowerShell)

Same steps in a terminal. Read the line ending with /var/jenkins_home and put its Name (volume) or Source (folder) in data= before running the rest.

old=jenkins-local
img=$(docker inspect $old --format '{{.Config.Image}}')
docker inspect $old --format '{{range .Mounts}}{{.Type}} | {{.Name}} | {{.Source}} -> {{.Destination}}{{"\n"}}{{end}}'
# data = the Name (volume) or the Source (folder) of the line ending with /var/jenkins_home
data=jenkinsvol
mkdir -p ~/jenkins-docker && cd ~/jenkins-docker
printf 'FROM %s\nUSER root\nCOPY --from=docker:29-cli /usr/local/bin/docker /usr/local/bin/docker\n' "$img" > Dockerfile
docker build -t jenkins-docker .
docker rm -f $old
docker run -d --name jenkins-local -u root -p 8080:8080 -p 50000:50000 -v "$data:/var/jenkins_home" -v /var/run/docker.sock:/var/run/docker.sock --add-host=host.docker.internal:host-gateway jenkins-docker
✅ Checkpoint 1: answer in report.txt, in your own words (one or two lines each).
  1. Jenkins in Docker: which option of docker run lets Jenkins use the Docker engine of your computer? Jenkins on Windows: why must Jenkins be started after Docker Desktop?
  2. You deleted the Jenkins container. Why are your jobs still there?
See the answer
  1. Jenkins in Docker: two changes were needed. The Dockerfile copied the docker program into the Jenkins image (COPY --from=docker:29-cli …), so the command is recognized. The option -v /var/run/docker.sock:/var/run/docker.sock of docker run connects that program (the client) to the Docker engine of your computer (the daemon), so the command works: that is why docker version shows a Client and a Server.
    Jenkins on Windows: a program reads the list of folders where commands are (the PATH) when it starts. A Jenkins started before Docker Desktop was installed does not know the docker command: it must be restarted.
  2. The jobs are not stored in the container: they are in /var/jenkins_home, which is a volume (like jenkinsvol) or a folder of the PC (a bind mount, like C:\jendoc). Deleting the container does not delete them, and the new container uses the same volume or folder with -v.
